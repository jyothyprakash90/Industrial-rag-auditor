# Industrial RAG Auditor — GenAI Compliance Assistant

A Retrieval-Augmented Generation (RAG) application that ingests long, unstructured
PDF audit reports and answers natural-language compliance questions grounded
strictly in the uploaded document — e.g. *"Does this factory meet ISO 9001
standards based on these notes?"*

Built to explore how GenAI can support audit and inspection workflows in
industrial/TIC (Testing, Inspection, Certification) contexts.

## How it works

1. **Ingest** — the uploaded PDF is parsed page-by-page and split into
   overlapping text chunks (`app/ingest.py`).
2. **Index** — each chunk is embedded using OpenAI embeddings and stored in a
   local Chroma vector database, scoped per uploaded report.
3. **Retrieve** — when a question is asked, the top-k most semantically
   relevant chunks are retrieved from Chroma.
4. **Generate** — the retrieved chunks are passed to `gpt-4o-mini` as context,
   with a system prompt that constrains the model to answer only from that
   context — reducing hallucination on compliance-sensitive answers.
5. **Cite** — the retrieved source chunks (tagged by page number) are shown
   alongside the answer so a user can verify it against the original report.

## Architecture

```
industrial-rag-auditor/
├── app/
│   ├── config.py        # centralized settings (models, chunk size, etc.)
│   ├── ingest.py         # PDF parsing, chunking, vectorstore creation
│   ├── rag_pipeline.py    # retrieval + LLM generation logic
│   └── main.py           # Streamlit UI (thin — no business logic)
├── requirements.txt
├── .env.example
└── README.md
```

Business logic is separated from the UI layer so the RAG pipeline itself
could be reused behind a different frontend (e.g. a REST API or React app)
without modification.

## Tech Stack

- **Python**
- **LangChain** — orchestration for chunking, embeddings, and LLM calls
- **ChromaDB** — vector store for semantic search
- **OpenAI API** (`gpt-4o-mini` + `text-embedding-3-small`)
- **Streamlit** — UI layer

## Setup

1. Clone the repo and install dependencies:
   ```bash
   git clone https://github.com/<your-username>/industrial-rag-auditor.git
   cd industrial-rag-auditor
   pip install -r requirements.txt
   ```

2. Add your OpenAI API key:
   ```bash
   cp .env.example .env
   # then edit .env and paste your key
   ```

3. Run the app:
   ```bash
   streamlit run app/main.py
   ```

4. Open the local URL Streamlit prints (usually `http://localhost:8501`),
   upload a PDF audit report, and ask a question.

## Design decisions worth noting

- **Context-grounded prompting**: the system prompt explicitly instructs the
  model to say "not enough information" rather than guess, which matters for
  compliance use cases where a wrong answer is worse than no answer.
- **Page-level citations**: each chunk is tagged with its source page during
  ingestion, so answers can be traced back to a specific part of the report —
  an important trust requirement for audit-facing tools.
- **Per-session vector store**: each uploaded report gets its own in-memory
  Chroma collection, so reports don't mix context across sessions.

## Possible extensions

- Persist the vectorstore to disk (`Chroma(persist_directory=...)`) to avoid
  re-embedding the same report across sessions.
- Add multi-document support for comparing several reports at once.
- Swap the OpenAI calls for Azure OpenAI to mirror an enterprise deployment
  pattern.
- Add automated evaluation of answer groundedness (e.g. using RAGAS).

## Disclaimer

This is a portfolio/demo project and is not a certified compliance tool.
Answers are generated by an LLM based on retrieved document text and should
not be relied on for real regulatory decisions.
